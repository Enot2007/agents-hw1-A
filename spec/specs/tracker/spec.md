# tracker Specification (delta)

## ADDED Requirements

### Requirement: Модель задачи и стартовые данные
Трекер MUST хранить задачи как записи `{ id, title, hours, done }`, где `id` уникален, `title` — непустая строка после trim, `hours` — число от 0,5 до 24, кратное 0,5, `done` — boolean. При первом запуске (без сохранённых данных) трекер MUST содержать ровно три задачи в таком порядке: «Чтение» 2 ч done=true, «Практика» 4 ч done=false, «Повторение» 2 ч done=false.

#### Scenario: Стартовые итоги примера
- **WHEN** трекер открыт впервые со стартовым примером
- **THEN** показано: всего 8 ч, выполнено 2 ч, прогресс 25%

### Requirement: Изменение данных действиями пользователя
Добавление, удаление и переключение `done` MUST менять сам массив задач. Интерфейс и итоги MUST перерисовываться по обновлённым данным, а не только по разметке.

#### Scenario: Отметить «Практику» готовой
- **WHEN** у «Практики» в стартовом примере включён признак done
- **THEN** выполнено 6 ч из 8 ч
- **AND** прогресс 75%

#### Scenario: Снять отметку обратно
- **WHEN** у «Практики» done сначала включён, затем выключен
- **THEN** выполнено 2 ч из 8 ч, прогресс 25%

#### Scenario: Добавление корректной задачи
- **WHEN** в стартовом примере добавлена задача «Конспект» на 2 ч
- **THEN** в данных 4 задачи, новая имеет done=false и уникальный id
- **AND** всего 10 ч, выполнено 2 ч, прогресс 20%

#### Scenario: Удаление задачи
- **WHEN** в стартовом примере удалена «Практика»
- **THEN** её нет ни в данных, ни в списке
- **AND** всего 4 ч, выполнено 2 ч, прогресс 50%

#### Scenario: Удаление всех задач
- **WHEN** удалены все задачи
- **THEN** итог 0 ч, выполнено 0 ч, прогресс 0%
- **AND** на странице нигде нет «NaN» или «Infinity»

### Requirement: Валидация ввода
Трекер MUST добавлять задачу только при корректном вводе. Название после trim непустое. Часы — число от 0,5 до 24 включительно с шагом 0,5. Пустое поле часов (или только пробелы) MUST считаться ошибкой «не заполнено», а не нулём. При ошибке задача MUST NOT добавляться. Сообщение MUST появиться рядом с соответствующим полем. Введённые значения MUST остаться в полях формы.

#### Scenario: Пустое название
- **WHEN** название пустое или из одних пробелов, часы равны 2
- **THEN** задача не добавлена, данные и итоги не изменились
- **AND** рядом с полем названия видна ошибка, в поле часов осталось «2»

#### Scenario: Пустые часы
- **WHEN** название «Тест», поле часов пустое
- **THEN** задача не добавлена
- **AND** рядом с полем часов видна ошибка о незаполненном поле, в поле названия осталось «Тест»

#### Scenario: Отрицательные часы
- **WHEN** название «Тест», часы −1
- **THEN** задача не добавлена, рядом с полем часов видна ошибка о диапазоне 0,5–24

#### Scenario: Ноль, вне диапазона, неверный шаг, не число
- **WHEN** часы равны «0», «24,5», «0,25», «1,3» или «abc»
- **THEN** задача не добавлена, рядом с полем часов видна ошибка

#### Scenario: Границы диапазона допустимы
- **WHEN** часы равны «0,5» или «24» при непустом названии
- **THEN** задача добавлена

### Requirement: Расчёт итогов и прогресса
Трекер MUST считать `total` как сумму `hours` всех задач, `doneHours` как сумму `hours` задач с done=true, а прогресс как `Math.round(100 × doneHours / total)`. Если `total` равен 0, прогресс MUST быть 0%. Итоги MUST всегда быть конечными числами.

#### Scenario: Нет задач
- **WHEN** список задач пуст
- **THEN** прогресс 0%, а не NaN% или Infinity%

### Requirement: Фильтр видимого списка
Трекер MUST предоставлять фильтр со значениями «Все» и «Активные» (done=false). Фильтр MUST влиять только на видимый список. Итоги и прогресс MUST считаться по всем задачам.

#### Scenario: Фильтр «активные»
- **WHEN** в стартовом примере выбран фильтр «Активные»
- **THEN** видны только «Практика» и «Повторение»
- **AND** всего 8 ч, выполнено 2 ч, прогресс 25%

#### Scenario: Отметка готовой при активном фильтре
- **WHEN** при фильтре «Активные» у «Практики» включён done
- **THEN** «Практика» пропадает из видимого списка, но остаётся в данных
- **AND** прогресс 75%

### Requirement: Читаемость и доступность
Интерфейс MUST быть читаем на ширине окна 390 px без горизонтальной прокрутки, в том числе при длинном названии без пробелов. Каждое поле ввода, фильтр, чекбокс done и кнопка удаления MUST иметь доступную подпись: `<label>` или `aria-label`, где в подписи есть название задачи. Сообщение об ошибке MUST быть программно связано со своим полем.

#### Scenario: Ширина 390 px
- **WHEN** страница открыта в окне шириной 390 px
- **THEN** `document.documentElement.scrollWidth` не больше `clientWidth`, все элементы управления видны и подписаны

### Requirement: Сохранение в localStorage (необязательное)
Если улучшение реализовано, трекер MUST сохранять задачи в localStorage после каждого изменения данных и загружать их при старте. Если хранилище недоступно или бросает исключение, трекер MUST показать понятное сообщение и продолжить работу в памяти без потери функциональности. Сохранённый пустой список MUST загружаться как пустой, без возврата стартового примера.

#### Scenario: Хранилище недоступно
- **WHEN** обращение к localStorage бросает исключение
- **THEN** видно сообщение, что данные сохраняются только до закрытия страницы
- **AND** добавление, удаление, переключение и итоги работают

#### Scenario: Перезагрузка после изменений
- **WHEN** хранилище доступно, «Практика» отмечена готовой, страница перезагружена
- **THEN** прогресс 75%

#### Scenario: Перезагрузка после удаления всех задач
- **WHEN** хранилище доступно, все задачи удалены, страница перезагружена
- **THEN** список пуст, итог 0 ч, прогресс 0%
